# Carte QR v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Application web auto-hébergée qui publie la carte de visite de Benjamin derrière un QR code, fournit la fiche contact (.vcf) avec photo, et récupère les coordonnées des visiteurs vers e-mail + Folk.

**Architecture:** Un seul processus Node (Hono) qui rend les pages côté serveur, une base SQLite fichier, un dossier `data/media` pour les photos. Les envois sortants (e-mail, Folk) passent par une file en base traitée par un worker interne. Tout le code métier reçoit ses dépendances (db, horloge, fetch, mailer) en paramètre pour être testable.

**Tech Stack:** Node 22, TypeScript (ESM), Hono + `@hono/node-server` + JSX Hono, `better-sqlite3`, `sharp`, `qrcode`, `nodemailer`, `@aws-sdk/client-s3`, `zod`, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-19-carte-qr-design.md`

## Global Constraints

- Interface entièrement en français, tutoiement exclu côté visiteur (vouvoiement sur les pages publiques), aucun emoji.
- Chaque table métier porte `user_id` (prêt multi-comptes). Inscription fermée : seul `ADMIN_EMAIL` peut se connecter.
- Pages publiques : aucun cookie, aucun script tiers, fonctionnent sans JavaScript.
- vCard 3.0, UTF-8, `text/vcard; charset=utf-8`, photo 400×400 JPEG q80.
- Image Open Graph 1200×630 JPEG.
- Lien magique : valable 15 min, usage unique. Session : 30 jours, cookie `HttpOnly; Secure; SameSite=Lax`.
- Formulaire d'échange : 5 envois max / heure / IP. Connexion : 5 demandes max / heure / IP.
- Upload photo ≤ 5 Mo, réencodé (métadonnées retirées).
- Folk : `POST https://api.folk.app/v1/people`, `Authorization: Bearer <FOLK_API_KEY>`, champs `firstName`, `lastName`, `emails`, `groups: [{id: FOLK_GROUP_ID}]`, `description`.
- Folk : nouvel essai toutes les 15 min, 5 essais max, puis statut `error`.
- Sauvegarde : chaque nuit à 03:00 Europe/Paris, 30 jours conservés sur S3.
- QR : correction d'erreur niveau M.
- Texte de consentement (version `v1`) : « J'accepte que Benjamin Vallée conserve ces coordonnées pour me recontacter dans un cadre professionnel. »
- Aucun stockage d'IP en clair (compteur de scans et rate limit en mémoire uniquement).

## Review Focus

1. Noms et valeurs avec accents, virgules, points-virgules, retours à la ligne dans la vCard : doivent être échappés selon vCard 3.0 et s'importer intacts sur iPhone et Android. Test dans Task 3.
2. Changement d'identifiant de carte (slug) : un QR déjà imprimé doit continuer à marcher. L'ancien slug redirige (301) vers le nouveau. Test dans Task 8.
3. Double envoi du formulaire (double appui, rechargement) : un seul contact créé si même carte + même e-mail/téléphone dans les 10 minutes, le visiteur voit quand même le remerciement. Test dans Task 5.
4. Photo invalide (PDF, fichier corrompu, HEIC non décodable, > 5 Mo) : message d'erreur clair dans l'administration, aucune exception non gérée. Test dans Task 3 et Task 8.
5. Numéros saisis avec espaces, points ou indicatif (`+41 79 …`, `06.12…`) : affichés tels quels, mais `tel:` et vCard reçoivent la forme sans espaces ni points. Test dans Task 3.
